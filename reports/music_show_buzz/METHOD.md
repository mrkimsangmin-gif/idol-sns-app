## 2. 파이프라인

```
collect_music_shows.py   → playlistItems + videos.list  → music-show-engagement.json (영상별 url 포함)
parse_title_to_group.py  → 채널별 제목 정규식 + group-aliases.json 매칭
analyze_buzz.py          → 정규화·세그먼트·랭킹       → music-show-buzz-ranking.json
collect_comments_ms.py   → commentThreads(영상당 상위 50) → music-show-comments.json
analyze_comments.py      → 언어구성·감정·키워드        → music-show-comment-analysis.json
```

### 2.1 수집 (`collect_music_shows.py`)
- `playlistItems.list`(50/page) 페이지네이션으로 video_id 수집 → `videos.list`(50/batch)로 조회수/좋아요/댓글/길이.
- 인증: `GOOGLE_API_KEY`(env, `06.jobs/credentials/secrets.cmd`와 동일 키). 쿼터: 전체 1회 ≈ 약 160 units.
- going-forward: 동일 스크립트 재실행으로 최신 스냅샷 갱신(주간 스케줄 부착 가능).

### 2.2 제목 → 그룹 매핑 (`parse_title_to_group.py`)
방송마다 제목 포맷이 달라 **채널별 정규식 4종**:
- 엠카: `{그룹} - {곡} #엠카운트다운`
- 뮤뱅: `{곡} - {그룹} [뮤직뱅크]` ← 그룹/곡 **순서 반대**
- 음중: `{그룹} ({한글}) - {곡} | Show! MusicCore`
- 인기가요: `{곡} - {그룹} | SBS YYMMDD 방송` (채널 업로드 정규 무대, 뮤뱅과 같은 곡-그룹 순서). 레거시 8K 풀캠 포맷 `[8K] {그룹} '{곡}' (FullCam)`은 파서가 인식만 하고 수집 대상에서 제외.

후처리: ① 선행 장식(`'COMEBACK'`/`'데뷔'`/`N위`) 제거, ② `A (B)` 영문·한글 병기 분리, ③ `group-aliases.json`(한글명+name_en+aliases, 1글자 alias 제외) 정규화 매칭.

### 2.3 분석 (`analyze_buzz.py`) — 전역 데이터 분석 프로토콜 준수
- **누적효과 보정**: 조회수 대신 **조회속도 = views / 업로드후경과일**. 오래된 영상의 누적 우위 제거.
- **세그먼트(`video_kind`)**: 현재 4사 모두 **단독 무대(stage)** 로 통합 집계(인기가요 포함). `fancam`은 레거시 8K 풀캠용 분류값이나 해당 소스는 미사용이라 실제 집계엔 stage만 존재. (※ 만약 풀캠 소스를 다시 넣으면 stage와 합산하지 말 것)
- **비공연 제외**: 인터뷰/MC/필러('컴백 인터뷰', '째빵즈' 등 곡 구조 없는 클립) 자동 분리.
- **품질 게이트**: `views==0`(인기가요 멤버십성 비공개) 제외, 업로드 `<3일`(velocity 불안정) 제외.
- **다지표**(단일지표 결론 금지):

| 지표 | 의미 |
|---|---|
| `velocity_sum` | 그룹의 윈도우 내 조회속도 총합 — **넓이×도달**(주지표) |
| `velocity_median` | 영상당 전형적 조회속도 — **반응 강도** |
| `eng_rate_mean` | (좋아요+댓글)/조회수 — **팬덤 화력 강도** |
| `shows_appeared` / `weeks_active` / `n_songs` | 활동 폭·지속성(로버스트성) |

> ⚠️ **`n_songs` 주의**: 곡명 정규화(어포스트로피 변형·괄호 제거) 적용했으나 여전히 표기 차이로 과대계상 가능. 활동 폭의 *대략적* 지표로만 사용(정밀 곡 수 아님).
> ⚠️ **`eng_rate` 스케일 의존**: 조회수가 분모라 **저조회 그룹일수록 eng%가 높게 튀는** 경향(소표본/소분모 효과). 규모가 다른 그룹 간 eng% 단순 비교 금지 — 비슷한 조회 규모 안에서만 "팬덤 화력" 해석.

- **윈도우**: 기본 최근 90일(`--days`). "최근 화제성" 질문에 맞춤.
- **영상별 URL**: 모든 영상에 `url`(watch?v=) 포함, 그룹 대표(최고조회) 영상 URL은 랭킹에 병기 → 수동 확인용.

### 2.4 댓글 내용 분석 (`collect_comments_ms.py` → `analyze_comments.py`)
- **수집**: `commentThreads.list`(영상당 상위 50개, `order=relevance`). 댓글 비활성 영상 스킵, 중간저장+재개 지원. 쿼터 ≈ 영상 1개당 1 unit.
- **언어 구성**: 유니코드 스크립트(한글/가나/한자/라틴/태국)로 댓글별 주 언어 판정 → 그룹 **해외 화제성 비중**(비한국어%). ⚠️ 수집이 `order=relevance`(유튜브 알고리즘 상위 노출 댓글)라 **전체 댓글의 국가 분포가 아니라 "상위 노출 댓글"의 분포**임. 로마자 멤버명·영어 그룹명도 영어로 오판될 수 있어 비한국어%는 *상한 근사*. 해외% 비교는 **표본 100개 이상** 그룹으로 한정.
- **감정(휴리스틱)**: 긍/부정 사전(이모지 포함) 카운트. *미검증 근사* — 음악방송 댓글은 부정 표현이 드물어 `긍%`는 응원·열정 밀도로 해석.
- **키워드**: 한글 어절(2자+)·영단어(3자+) 빈도, 불용어 제거 → 멤버명·응원어 surface(형태소 분석 미적용).
- **주의**: 댓글 수는 영상당 ≤50 **표본**이라 활동량(영상 수)에 비례 → 절대 댓글량은 화제성 랭킹의 comment count 사용.

## 3. 해석 규칙 (필수)
- **활동량 vs 반응강도 분리**: `velocity_sum`(다출연 누적)과 `velocity_median`(영상당)·`eng_rate`(팬덤)를 분리 보고. 예: 베이비몬스터는 3영상이지만 영상당 14만(고강도), 코르티스는 20영상 누적(넓은 활동).
- **팬덤 화력 ≠ 대중 화제성**: `eng_rate` 높고 `velocity` 낮으면 충성 팬덤형(조회 대비 결집), 반대면 대중 도달형.
- **투명성(silent cap 방지)**: 174그룹 패널 외(솔로·신인)로 제외된 고조회 출연자를 `top_unmatched_performance`에 surface.

## 4. 한계 (반증·red-team)
- **인기가요 커버리지**: 채널 업로드 최근 ~30페이지 스캔 → 정규 무대 494개. 더 과거는 `max_pages` 상향 필요. 8K 풀캠은 viewCount 비공개라 제외.
- **단일 스냅샷**: velocity는 누적 조회수의 시간평균 근사이지 "초기 7일 조회수"가 아님. going-forward 시계열 수집 시 고정창(업로드후 N일) 비교로 정밀화 가능.
- **활동 그룹 한정**: 컴백 안 한 그룹은 영상 부재 = 측정 불가(낮은 화제성 아님).
- **패널 경계**: `group-aliases.json` **174그룹** 기준. 아이오아이(2026 재결합)·KATSEYE·NCT WISH·CUTIE STREET 등은 패널 외 → 별도 surface. 아이오아이/태양 등은 한글/영문 표기 분리로 이중 카운트(병합 시 상위권). (※ XLOV/엑스러브는 **이미 패널 포함**, Top 25 8위.)
- **velocity 최신성 편향**: 단일 스냅샷 `views/경과일`은 K-pop 무대의 초동 급상승→감쇠(로그 곡선) 특성상 **최근 업로드 그룹이 구조적으로 유리**. 컴백이 윈도우에 막 걸린 그룹(에스파·베이비몬스터 2주차 등)은 velocity가 부풀려짐 → 순위는 활동주수와 함께 해석. **근본 해소는 going-forward 고정창(업로드후 N일 조회수) 수집 필요**.
- **매스미디어 trigger 인과 주의**: 방송 출연이 화제성의 원인인지 결과인지 단정 금지(방송일↔조회 급증 시점 직접 비교 필요).
